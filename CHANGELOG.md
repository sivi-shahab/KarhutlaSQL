### Fixed
- Nama tabel dari EXPLAIN yang ber-kutip (catalog/schema/tabel bernama keyword, mis. `"secret".main.k`) kini di-unquote; sebelumnya grant pada objek tersebut tidak pernah cocok (Fase 5).
- Verifikasi token lokal kini menoleransi selisih jam 1 menit (seperti OIDC): saat jam mundur (sinkronisasi NTP/WSL) token yang baru diterbitkan ditolak `invalid or expired token` karena `iat` di masa depan (Fase 2).
- `DROP TABLE` dengan nama 4 bagian (`a.b.c.d`) kini ditolak langsung oleh extractor target tulis (sebelumnya baru ditolak saat resolusi nama; ditemukan `FuzzWriteTargets`).
- `make` mengambil versi dari tag `v*` saja (sebelumnya tag `backup/*` ikut terbaca sebagai versi).
- `CALL karhutla_*` kini dianalisis (EXPLAIN): fungsi kontrol admin tidak lagi antre di scheduler dan `CALL` fungsi aman tidak butuh admin global (Fase 6).

### Changed
- Versi Go minimum efektif 1.25 (dipaksa arrow-go/grpc sejak Fase 1; `go.mod` `go 1.25.0`). CONTRIBUTING diperbarui.
- Versi Go minimum 1.26 (`golang.org/x/net` v0.60, perbaikan keamanan; Fase 7).
- `--query-profiling` kini default mati (biaya ~13% waktu eksekusi TPC-H SF10); `peak_memory_bytes`/`plan_hash` di `karhutla_query_history()` NULL kecuali diaktifkan. Helm `queryProfiling: false`.
- Hasil query dikirim dalam batch Arrow ±64k baris (sebelumnya 2048 baris per vektor DuckDB).
- Spec Q-03: sanitasi hasil GX menjadi allowlist field `result` (ADR 12). K-03: storage path placeholder `file:///karhutlasql-unreadable/...`, UC tanpa kredensial bucket, grant di level schema/catalog (ADR 13).
- Nama proyek diganti dari GarudaSQL menjadi KarhutlaSQL (binary `karhutlasql-*`, env `KARHUTLASQL_*`, prefix fungsi SQL & metrics `karhutla_*`).
- Backlog: read-replica copy-file diganti DuckLake (Postgres + MinIO) sebagai topologi multi-writer v2.
- SECURITY.md: tambah peta kepatuhan UU PDP / POJK dan kebijakan rewriter fail-closed, secret temporary-only, WORM.

### Security
- `golang.org/x/net` v0.58 → v0.60 dan `golang.org/x/crypto` v0.55 → v0.57: 5 kerentanan HTTP/2 (GO-2026-6603, -6610, -6611, -6612, -6617) yang terjangkau dari server gRPC dan klien UC; govulncheck kini bersih.
- Prepare statement multi-statement (`CreatePreparedStatement("DROP TABLE x; SELECT 1")`) tidak lagi mengeksekusi statement selain yang terakhir (duckdb-go `PrepareContext`); semua SQL user kini ditolak bila lebih dari satu statement.
- Non-admin tidak bisa lagi membaca file server lewat table function (`read_csv`, `'file.csv'`, `glob`, …) atau `ATTACH`/`COPY`/`SET`.
- Kill session OIDC tidak bisa dihindari dengan refresh token (revocation per `sid`, minimal 24 jam).
